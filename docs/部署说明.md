# 部署说明

本文说明如何在单台 Linux 服务器上使用 Docker Compose 部署大学生健康管理平台。文中的 `<SERVER_IP>`、`<DOMAIN>`、`<PASSWORD>` 需要替换为实际值。

> 更详细的 Compose 目录、旧容器迁移和排错说明见 [`deploy/compose/README.md`](../deploy/compose/README.md)。

## 1. 部署拓扑

```text
浏览器 / 手机 App
   │
   ▼
Nginx
   ├── :80   PC 管理端（history 路由）
   ├── :8080 App H5 + /download/ 下载页
   ├── /api      -> backend:8888
   └── /uploads  -> backend:8888
                       │
                       ├── MySQL 3306（仅内网）
                       └── Redis 6379（仅内网）
```

- 公网只放行 `22`、`80`、`8080`
- `3306`、`6379`、`8888` 不对外暴露
- 后端只在宿主机 `127.0.0.1:8888` 发布，方便本机排查

## 2. 服务器要求

- Linux（CentOS / Alibaba Cloud Linux / Ubuntu 均可）
- Docker 20.10+
- Docker Compose v2（`docker compose version`）
- 建议 2G 内存 + 2G swap，至少 5G 磁盘
- 已备案域名可选；没有域名可以先用公网 IP + HTTP

安装 Compose v2：

```bash
docker compose version || sudo dnf install -y docker-compose-plugin
# Ubuntu: sudo apt install -y docker-compose-plugin
```

## 3. 本地构建产物

服务器不安装 JDK/Maven/Node，所有产物在本地构建后上传。

### 3.1 后端 jar

```bash
cd backend
mvn clean package -DskipTests
```

产物：

```text
backend/health-web-mng/target/health-web-mng-1.0.0.jar
```

### 3.2 PC 管理端

```bash
cd frontend/pc
npm ci
npm run build
```

产物：`frontend/pc/dist/`。

### 3.3 学生端 H5

```bash
cd frontend/app
npm ci
npm run build:h5
```

产物：`frontend/app/dist/build/h5/`。

### 3.4 Android APK

```powershell
cd frontend/app
$env:VITE_API_BASE_URL="http://<SERVER_IP>:8080/api"
npm run build:app
```

然后在 HBuilderX 中导入 `frontend/app/dist/build/app/` 并云打包。`manifest.json` 的 `appid` 需要替换成你自己的 DCloud appid。

> 正式环境建议使用 HTTPS：`VITE_API_BASE_URL=https://<DOMAIN>/api`，并同步调整 `manifest.json` 的网络安全配置。

## 4. 服务器目录

把 Compose 目录上传到服务器 `/opt/project/compose/`，最终布局：

```text
/opt/project/
├── compose/
│   ├── docker-compose.yml
│   ├── .env
│   └── nginx/
│       ├── conf.d/health.conf
│       └── snippets/health-api.conf
├── jar/
│   └── health-web-mng-1.0.0.jar
├── backend/
│   └── config/application-prod.yml
├── docker/
│   ├── mysql/data/
│   ├── redis/data/
│   └── nginx/
│       ├── html/
│       │   ├── health-pc/
│       │   ├── health-app/
│       │   └── download/
│       │       ├── index.html
│       │       ├── logo-192.png
│       │       └── health-app.apk
│       ├── ssl/
│       └── logs/
├── files/
├── backup/
├── logs/
└── sql/
    ├── schema.sql
    └── demo-data.sql
```

创建目录：

```bash
sudo mkdir -p /opt/project/{compose,jar,backend/config,docker/mysql/data,docker/redis/data}
sudo mkdir -p /opt/project/docker/nginx/{html/health-pc,html/health-app,html/download,ssl,logs}
sudo mkdir -p /opt/project/{files,backup,logs,sql}
sudo chmod 700 /opt/project/backend /opt/project/compose
```

上传产物：

| 本机文件 | 服务器位置 |
| --- | --- |
| `backend/health-web-mng/target/health-web-mng-1.0.0.jar` | `/opt/project/jar/` |
| `frontend/pc/dist/*` | `/opt/project/docker/nginx/html/health-pc/` |
| `frontend/app/dist/build/h5/*` | `/opt/project/docker/nginx/html/health-app/` |
| `frontend/app/deploy/download/*` | `/opt/project/docker/nginx/html/download/` |
| Android APK（重命名为 `health-app.apk`） | `/opt/project/docker/nginx/html/download/` |
| `deploy/docker/application-prod.yml` | `/opt/project/backend/config/application-prod.yml` |
| `sql/schema.sql`、`sql/demo-data.sql` | `/opt/project/sql/` |
| `deploy/compose/*` | `/opt/project/compose/` |

APK 必须命名为 `health-app.apk`，否则下载页和 PC 扫码入口会 404。

## 5. 环境变量

```bash
cd /opt/project/compose
cp .env.example .env
chmod 600 .env
vi .env
```

至少填写：

```env
DB_NAME=health_management
DB_USERNAME=health
DB_PASSWORD=<强密码>
MYSQL_ROOT_PASSWORD=<MySQL root 密码>
REDIS_PASSWORD=<Redis 密码>
JWT_SECRET=<openssl rand -hex 32 生成>
DASHSCOPE_API_KEY=<可选>
```

说明：

- 沿用已有 MySQL 数据目录时，`MYSQL_ROOT_PASSWORD` 不会修改现有 root 密码，但 Compose 仍要求填写，可填占位值
- `DB_USERNAME` / `DB_PASSWORD` 必须与现有 `health` 用户一致
- `.env` 含真实密钥，权限保持 `600`，不要提交到 Git

## 6. 数据库初始化

### 全新数据库

保持 `/opt/project/docker/mysql/data` 为空，Compose 首次启动会自动执行：

```text
01-schema.sql    # 23 张表的完整结构
02-demo-data.sql # 角色、菜单、字典、系统参数、演示管理员
```

演示管理员：

```text
admin / 123456
```

**部署后请立即修改密码。**

### 已有数据

先备份旧库，再停掉旧 MySQL/Redis/后端/Nginx 容器，把旧数据目录保留到 `/opt/project/docker/mysql/data`，然后启动 Compose。不要同时运行两个 MySQL 进程写同一个数据目录。

```bash
# 示例：旧 MySQL 容器仍运行时备份
docker exec -i mysql8 mysqldump -uroot -p'<root密码>' \
  --default-character-set=utf8mb4 health_management \
  > /opt/project/backup/health_management-before-compose.sql
```

> MySQL 大版本必须匹配。8.0 的数据目录不能直接挂给 5.7，反之亦然。

## 7. 启动

```bash
cd /opt/project/compose
docker compose up -d
docker compose ps
docker compose logs -f backend
```

验证：

```bash
curl -I http://127.0.0.1/
curl -I http://127.0.0.1:8080/
curl -I http://127.0.0.1/download/
curl -I http://127.0.0.1/download/health-app.apk
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8888/
```

访问：

- PC：`http://<SERVER_IP>/`
- App H5：`http://<SERVER_IP>:8080/`
- 下载页：`http://<SERVER_IP>/download/`（PC 同源，扫码用这个）或 `http://<SERVER_IP>:8080/download/`

## 8. 下载页与二维码

PC 登录页和顶部栏都有“下载学生端 App”入口：

- 桌面浏览器：弹出二维码
- 手机浏览器：直接跳下载页
- 二维码默认使用当前 PC 访问地址 + `/download/`，不写死 IP
- 如需指向其他地址，构建 PC 时设置 `VITE_APP_DOWNLOAD_URL`

Nginx 的 80 和 8080 都配置了 `/download/`。如果扫码后看到的是 PC 登录页而不是下载页，说明服务器上的 Nginx 还是旧配置，重新上传 `deploy/compose/nginx/conf.d/health.conf` 并重启 Nginx。

微信/QQ 内置浏览器会拦截 APK 下载，下载页会提示用户在浏览器打开。APK 下载后仍需用户确认安装未知来源应用。

## 9. 更新与回滚

```bash
cd /opt/project/compose

# 更新后端 jar 后
docker compose restart backend

# 更新前端静态文件：替换 dist 内容即可
# 更新 Nginx 配置后
docker compose restart nginx

# 修改 .env 或 application-prod.yml 后
docker compose up -d --force-recreate backend

# 更新镜像
docker compose pull
docker compose up -d
```

回滚：

- 后端：保留上一版 jar，替换后重启 backend
- 前端：保留上一版 dist 目录
- 数据库：使用部署前的 mysqldump 备份恢复

## 11. 常见问题

```bash
docker compose ps
docker compose logs -f mysql
docker compose logs -f redis
docker compose logs -f backend
docker compose logs -f nginx
ss -lntp | grep -E ':80|:8080|:8888|:3306|:6379'
```

| 现象 | 处理 |
| --- | --- |
| `port is already allocated` | 旧容器占用 80/8080/8888，先 `docker rm -f` 旧容器 |
| MySQL 启动后退出 | 看 `docker compose logs mysql`；检查数据目录权限和大版本 |
| 后端连不上 MySQL | 检查 `.env` 的 `DB_USERNAME` / `DB_PASSWORD` |
| 后端 502 | `docker compose ps` 确认 backend 已启动，必要时 `docker compose restart nginx` |
| `/download/` 显示 PC 登录页 | Nginx 80 端口缺少 `/download/` 配置，更新配置并重启 |
| APK 404 | 文件没有命名为 `health-app.apk` 或没有上传到 `html/download/` |
| SQL 文件挂载成目录 | 源文件不存在，Docker 创建了同名目录；先 `rmdir` 再上传文件 |
| 数据目录权限错误 | `sudo chown -R 999:999 /opt/project/docker/mysql/data /opt/project/docker/redis/data` |

## 12. 旧版手工 Docker / 非 Docker 部署

`deploy/docker/` 保留了旧的手工 `docker run` 配置，`deploy/nginx/` 和 `deploy/health-backend.service.example` 保留了非 Docker 的 Nginx/systemd 示例。

新部署建议使用 `deploy/compose/`；旧配置仅用于已有服务器的迁移参考。
